# Dev：开发自测

通常由 **`dev-build` 编排调用**；也可在实现后单独触发。

**自测**验证「代码按 Plan 的设计工作」。它 **不是** QA 测试，不能替代验收 —— 详见项目 `AGENTS.md` §10。

| | 开发自测 | QA 测试 |
|---|---|---|
| 依据 | Plan 的 **DST-xxx** | 需求规格 / **TC-xxx** |
| 判定人 | 开发本人 | QA |
| 编号 | `DST-xxx` | `TC-xxx` |
| 位置 | 源码旁、`e2e/tests/dev/`；记录在 feature 目录 | `docs/` 用例库、`e2e/tests/qa/` |
| 合并闸门 | 否 | **是** |

## 前置

1. 读对应 plan 的 DST 场景表（§8～10）与同目录 `*-progress.md`
2. **先起真实本地环境**，禁止只靠「未起服务的纯编译」冒充集成/API/E2E 通过

## 真实本地环境（硬性）

按项目惯例拉起依赖与进程，再用 `localhost` 打服务：

1. 依赖：DB（如 MySQL）与迁移按项目 README / `AGENTS.md`
2. 后端：监听 `8080`
3. 有前端 DST / E2E 时：前端 `5173`；优先 `./e2e-run.sh` 一键拉齐
4. **健康检查**通过后再跑集成/API/E2E（如 `http://localhost:8080/actuator/health` 或项目约定）
5. 环境起不来 → 记入记录为失败并修环境；**不得跳过标通过**

单元测试可先于服务启动执行；**集成 / API / E2E 必须打已启动的本地服务**。

## 执行顺序

```
0. 启动真实本地环境 + 健康检查
1. 后端单元测试     →  秒级
2. 后端集成 / API   →  打 localhost 后端
3. 前端类型/构建    →  秒级
4. 前端单元测试     →  秒级
5. E2E 自测         →  打本地前后端（e2e tests/dev）
```

```bash
# 环境（示例；以项目脚本为准）
./e2e-run.sh

cd containers/backend && mvn test
cd containers/frontend && npm run build

cd e2e && npm run test:dev   # 开发自测 E2E，不含 QA 用例
```

## 按 DST 执行

- 逐条核对 plan 中的 DST：已实现对应用例并执行
- **未覆盖的 DST = 失败项**，不得宣称自测通过
- 实现后可选更新 `docs/test-cases/dev-self-cases/` 索引

## 失败处理

### 先分类，再动手

| 症状 | 多半是 | 动作 |
|---|---|---|
| 断言失败，但代码逻辑看着对 | **实现错了** | 改实现 |
| 断言失败，值差一点点 | 边界没考虑到 | 补实现 + 补边界用例 |
| 测试报空指针 / NPE | 测试前置数据缺失 | 补测试数据准备 |
| 连不上端口 / 健康检查失败 | **环境未就绪** | 先修环境，别改断言 |
| 整类用例一起挂 | 环境问题（DB、端口、依赖） | 先修环境 |
| 用例之间互相影响 | 测试没有隔离 | 修测试隔离 |
| 昨天绿今天红 | 时间/顺序依赖 | 显式等待，去掉硬等待 |

### 绝对不要做

- ❌ 改断言迁就实现；删用例；随意 `@Disabled` / `skip`
- ❌ 改 **QA 用例**（`e2e/tests/qa/`）
- ❌ 环境没起来却标自测通过

若 Plan/DST 错了：**回到 Plan**，不要悄悄改口径。

## 覆盖自查

| 项 | 要求 |
|---|---|
| plan 每条 DST | 有结果行 |
| 每个新增/修改的 API | Happy Path + 关键失败分支 |
| 每个新聚合 | 不变量有用例 |
| 每个状态流转 | 合法 + 非法各一条 |
| 前端新组件 | 单元测试（若适用） |
| DB 变更 | 迁移 + 测试 schema 同步 |
