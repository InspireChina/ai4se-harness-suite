# 估算基线表

> 需求分类 → 基线点数。数字是 **起点**，靠 `pm-retro` 校准。
>
> 点数单位是"相对点数"，不是人日。转人日要用团队基线（见 `pm-estimate`）。

## 一、基线表

| 分类 | 基线点数 | 包含什么（默认范围） |
|---|---:|---|
| **展示型** | 1 | 静态页面/只读列表，无交互逻辑、无新接口 |
| **表单型** | 2 | 单表单增改改，前端校验 + 1 个 CRUD 接口，无状态流转 |
| **列表查询型** | 3 | 带筛选/排序/分页的列表，复用现有列表组件与查询模式 |
| **详情型** | 3 | 单条详情展示，含空态/加载态，无写操作 |
| **CRUD 型** | 5 | 完整增删改查，后端含持久化、校验、权限 |
| **状态流转型** | 5 | 引入状态机与流转守卫，含非法流转处理与并发冲突 |
| **规则型** | 5 | 引入业务规则引擎、规则配置或数据字典注册 |
| **集成型** | 8 | 对接外部服务/第三方 API，含鉴权、失败重试、幂等 |
| **报表型** | 8 | 统计聚合、跨表查询、导出 |
| **权限型** | 8 | 新增角色或细粒度权限模型，含数据范围控制 |
| **数据迁移型** | 8 | 历史数据订正、字段回填、双写兼容期 |
| **性能型** | 8 | 明确性能瓶颈的优化（需先有基线数据） |
| **缺陷修复型** | 1 | 明确根因、改动范围小的缺陷（1 点起，按复杂度调整） |
| **缺陷排查型** | 2 | 根因不明、需要先定位的缺陷（定位 + 修复） |
| **技术重构型** | 5 | 不改外部行为、只改内部结构的重构 |
| **架构级改造** | 13 | 分层调整、框架替换、数据模型重构 |

## 二、复杂度系数

在基线点数上乘。

| 系数 | 判定 |
|---:|---|
| 0.8 | 简单。改动 < 3 个文件，无新概念，有现成实现可复制 |
| 1.0 | 标准。改动 3~8 个文件，涉及 1~2 层，可能新增 1 个接口 |
| 1.4 | 复杂。改动 > 8 个文件，跨 3 层以上，有并发/事务/兼容性考虑 |

## 三、风险系数

在基线点数上乘。

| 系数 | 判定 |
|---:|---|
| 1.0 | 低。技术成熟、有现成模式、依赖稳定 |
| 1.2 | 中。存在未知点、需联调、依赖第三方、历史数据不干净 |
| 1.5 | 高。核心链路、有数据迁移、需求本身可能变、依赖外部团队 |

## 四、分类选择决策

```
只读展示，无新接口            → 展示型
一个表单，无状态流转          → 表单型
列表要筛选/分页/排序          → 列表查询型
新角色 / 数据范围 / 权限矩阵   → 权限型
状态会变，且有非法流转        → 状态流转型
要落新业务规则或枚举字典      → 规则型
要改库表结构或回填历史数据    → 数据迁移型
要调外部 API                  → 集成型
没有外部行为变化的重构        → 技术重构型
```

**同时命中多个**：按 **点数最高的那个** 估，并在说明里写清命中了哪些。

## 五、常见条目组合示例

| 需求 | 拆解 | 基线 | 最终 |
|---|---|---|---:|
| 预约列表 + 取消预约 | 列表查询型 3 + 状态流转型 5 | | 3.0 + 8.4 = 11.4 |
| 后台加一个统计看板 | 报表型 8 + 展示型 1 | | 8.0 + 0.8 = 8.8 |
| 接入短信验证码 | 集成型 8 + 表单型 2 | | 11.2 + 1.6 = 12.8 |
| 修一个日期显示错位 | 缺陷修复型 1 | 复杂 1.4 | 1.4 |
| 用户表加字段并回填 | 数据迁移型 8 + 规则型 5 | | 8.0 + 5.0 = 13.0 |

## 六、团队基线

点数转人日需要一个 **团队基线**（1 点 = 多少人日），它随团队熟练度变化：

| 团队状态 | 建议基线 |
|---|---|
| 熟悉本代码库 | 0.4 ~ 0.5 人日/点 |
| 一般熟悉 | 0.5 ~ 0.7 人日/点 |
| 刚接触 | 0.7 ~ 1.0 人日/点 |

**首次使用时先估 5 条有历史记录的需求，反推基线**，不要直接套上表。

## 七、校准规则

每次迭代结束：

1. 对比估算点数与实际耗时
2. 偏差 > 30% 的条目，逐条写原因
3. 连续两次同类偏差 > 30% → 调整该分类的基线点数
4. 调整要 **改基线表 + 写明原因**，不要只改一次估算
