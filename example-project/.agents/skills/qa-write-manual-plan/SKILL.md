# QA：编写手动测试与冒烟计划

自动化的盲区用手动补，发版前的判断用冒烟做。

## 输出位置

| 产物 | 位置 | 编号 |
|---|---|---|
| 手动测试用例 | `docs/test-cases/manual-cases/manual-test-cases.md` | `TC-Mxx` |
| 冒烟用例 | `docs/test-cases/smoking-cases/smoking-test-cases.md` | `TC-Sxx` |

## 一、什么场景需要手动

| 场景 | 为什么自动化不了 |
|---|---|
| 视觉判断（好不好看、像不像原型） | 断言不了"好看" |
| 主观体验（流畅度、易用性） | 没有客观判据 |
| 跨设备/跨浏览器差异 | 环境成本高 |
| 弱网/断网/异常权限组合 | 难以稳定构造 |
| 第三方服务真实交互 | 沙箱不稳定 |

**先自查：真的自动化不了吗？** 能自动化的不要塞进手动 —— 手动用例会烂尾。

## 二、手动用例格式

```markdown
| # | 用例 | 前置条件 | 步骤 | 预期 | 执行人 |
|---|---|---|---|---|---|
| TC-M01 | 后台禁用用户后其登录态失效 | 存在普通用户 user@test.com | 管理员禁用该用户 → 用户端刷新页面 | 用户被强制登出，跳转登录页 | |
```

| 列 | 要求 |
|---|---|
| `#` | `TC-Mxx`，与 `TC-xxx` 不共用编号空间 |
| 前置条件 | **可复现**的初始状态（账号、数据、时间） |
| 步骤 | 编号步骤，执行人不需要问"然后呢" |
| 预期 | 可观察的具体结果 |
| 执行人 | 执行后签字 |

要求：

- 每条用例 **独立可执行**，不依赖上一条的结果
- 前置数据写清楚怎么准备（种子数据 / 手工造数）
- 写明 **环境**：哪个环境、哪个分支
- 一次执行完一批，逐条打勾

## 三、冒烟用例集

目标：**5 分钟内跑完**，回答一个问题 —— **能不能发**。

选择原则：

- 只选 **P0 冒烟点**：服务起不来、登录不了、核心链路断了、数据库连不上
- 不选业务细节（那些是回归的事，不是冒烟的事）
- 每个冒烟点尽量能自动化 → 在 `e2e/tests/qa/` 里也有对应自动化
- **核心链路必须写成具体的一条**（如 `TC-S03 核心链路`：登录 → 建单 → 提交 → 审核 → 质量流转），步骤与预期可照做；表里留 `TODO` 等于这一关不存在

```markdown
| # | 用例 | 冒烟点 | 预期 | 自动化 |
|---|---|---|---|---|
| TC-S01 | 服务启动 | 后端可启动、前端可加载 | 无启动错误，首页 200 | `qa/app.spec.ts` → Public Pages |
| TC-S02 | 登录 | 管理员正确凭据登录 | 跳转到 `/admin/dashboard` | `qa/app.spec.ts` → Auth |
| TC-S03 | 核心预约链路 | 选咨询师 → 选时间 → 提交 | 预约成功，出现在预约列表 | `qa/app.spec.ts` → User Flows |
| TC-S04 | 管理端可读 | 管理员查看用户/预约列表 | 列表正常渲染 | `qa/app.spec.ts` → Admin Flows |
| TC-S05 | 数据库连通 | 写入后可读回 | 无连接错误 | `qa/app.spec.ts` |
```

**5 条以内。** 超过 5 分钟就不是冒烟了。

## 四、两者与 QA 自动化用例的关系

| | 手动 `TC-Mxx` | 冒烟 `TC-Sxx` | 自动化 `TC-xxx` |
|---|---|---|---|
| 位置 | `docs/test-cases/manual-cases/` | `docs/test-cases/smoking-cases/` | `docs/test-cases/e2e-cases/` + `e2e/tests/qa/` |
| 频率 | 每次验收 | 每次发版 | 每次提交 |
| 覆盖 | 自动化的盲区 | P0 最小集 | 需求全量 |
| 判定 | QA | QA | QA |

**冒烟用例应该是自动化用例的子集**，不是另一套。

## 五、与发布的关系

冒烟用例是发版准备的最后一关：

1. 开发自测全绿 → `dev-self-test`
2. QA 验收用例集全绿 → `qa-run-e2e`
3. 手动用例执行完毕 → 本 skill
4. 冒烟用例全绿 → 允许发布 → `dev-release-plan`

**手动用例没执行完，不能发版。** 不要用"自动化都过了"替代。

## 自检清单

- [ ] 每条手动用例独立可执行，前置条件写清楚
- [ ] 步骤是编号步骤，执行人不用追问
- [ ] 预期是可观察结果
- [ ] 冒烟用例 ≤ 5 条、≤ 5 分钟
- [ ] 核心链路冒烟点已写成具体步骤与预期，表内没有 `TODO`
- [ ] 冒烟点都是 P0，不是业务细节
- [ ] 能自动化的冒烟点已关联到自动化用例
- [ ] 编号空间不混用（`TC-` / `TC-M` / `TC-S`）
- [ ] 与 `docs/test-cases/e2e-cases/test-cases.md` 的编号不重复
