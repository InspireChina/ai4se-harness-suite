# QA：运行 E2E

跑 QA 用例集，判通过，失败时定位到 **根因** 而不是症状。

## 运行

```bash
cd e2e && npm run test:qa
```

完整流程（含启动前后端）：

```bash
./e2e-run.sh
```

| 命令 | 作用 |
|---|---|
| `npm run test:qa` | 只跑 QA 验收用例（合并闸门） |
| `npm run test:dev` | 只跑开发自测用例（不阻塞合并） |
| `npm test` | 全部 |

调试单个用例：

```bash
cd e2e
npx playwright test --project=qa --grep "TC-013"
npx playwright test --project=qa --headed --debug   # 有头 + 调试器
```

## 前置检查

跑之前先确认环境，别把环境问题当成用例失败：

- [ ] 后端已启动，`http://localhost:8080` 可访问
- [ ] 前端已启动，`http://localhost:5173` 可访问
- [ ] 数据库可用（测试库已初始化）
- [ ] 种子数据存在（咨询师、网点等）
- [ ] 上一次运行没留下脏数据

## 失败分类（先分类，再处理）

| 现象 | 归类 | 处理 |
|---|---|---|
| 所有用例都失败，连首页都打不开 | **环境** | 修环境，不要动用例 |
| 某一条失败，单独跑也失败 | **实现 bug** | 提缺陷给开发 |
| 某一条失败，单独跑能过 | **用例没隔离** | 修用例（数据清理/顺序依赖） |
| 时好时坏 | **Flaky** | 找硬等待/时间依赖，**不能靠重试掩盖** |
| 报错信息不明确 | **断言太弱** | 补具体断言，让失败可读 |
| 需求本身有歧义 | **规格问题** | 找 PO 澄清，不在代码里猜 |

**"重试一次就过了" 不等于通过。** Flaky 用例必须修，否则闸门形同虚设。

## 定位流程

```
1. 看失败用例的名字与编号        → 确定是哪条 TC
2. 单独重跑，确认是否稳定失败     → 排除偶发
3. 看 trace / 截图               → playwright-report/ 里看
4. 看控制台报错                  → list_console_messages
5. 看失败的网络请求              → list_network_requests
6. 看页面快照                    → take_snapshot
7. 对照规格                      → 是实现不符还是用例写错
```

判定归属：

- 规则编号明确、实现不符 → **实现 bug**
- 规则编号明确、实现符合但与理解不一致 → **用例写错**，改用例
- 规则编号不明确 / 规格没覆盖 → **规格有歧义**，找 PO

## Flaky 常见原因

| 原因 | 修法 |
|---|---|
| 硬等待 `waitForTimeout` | 换成显式等待（`expect(...).toBeVisible({timeout})`） |
| 依赖上一条用例的数据 | 每条用例自己准备数据 |
| 依赖当前时间/日期 | 固定时间（注入或 mock） |
| 动画未结束就断言 | 等元素稳定，或用 `toHaveText` 而非 `toBeVisible` |
| 并发用例抢数据 | 用例串行化，或数据加唯一后缀 |
| 重试掩盖了真问题 | 找到根因，不要靠 `retries` |

## 报告

```
E2E 验收：<通过 / 有失败>
- QA 用例：N/N 通过（对应 docs/test-cases/e2e-cases/test-cases.md）
- 耗时：X 分 Y 秒

失败明细：
| 用例 | 归类 | 现象 | 证据 | 归属 |
|---|---|---|---|---|
| TC-013 预约 + 取消 | 实现 bug | 取消后状态仍为 PENDING | trace + 截图 | 开发 |

未覆盖：
- TC-018 预约管理（用例尚未实现）
```

**如实报告。** 没跑的用例要写进"未覆盖"，不能默认算通过。

## 结论

| 结论 | 条件 |
|---|---|
| ✅ 通过 | QA 用例集全绿 + 文本用例逐条勾选 |
| 🔄 有失败 | 列出失败明细与归属 |
| ⚠️ 未覆盖 | 有用例未实现或有锚点无用例 —— **不能判通过** |
