# 代码规范（事实）

本目录是 **代码层面的硬约束**，写明"必须怎么做"。改动规范时要同步改本目录，并通知全队。

## 规范清单

标注 **预置** 的文件由安装器直接生成；**按需创建** 的在对应能力落地时再补，不要留个空壳假装有规范。

| 文件 | 状态 | 规范内容 |
|---|---|---|
| `architecture.md` | 预置 | 整体架构、模块边界、依赖方向 |
| `layers.md` | 预置 | 分层职责：每层允许做什么、禁止做什么 |
| `naming.md` | 预置 | 命名约定：包、类、方法、字段、REST 路径 |
| `test.md` | 预置 | 测试规范：用例归属、覆盖要求、数据准备、闸门 |
| `adr.md` | 预置 | 架构决策记录（ADR）写法；正文落在 `docs/architecture/tech/adr.md` |
| `templates/` | 预置 | 代码模版 / snippet / ADR 模板，供复制 |
| `api-design.md` | 按需创建 | API 设计：路径、版本、请求响应、分页、状态码 |
| `db.md` | 按需创建 | 数据库规范：建表、命名、索引、迁移脚本 |
| `error.md` | 按需创建 | 错误处理：错误码、异常类型、统一响应体 |
| `security.md` | 按需创建 | 安全规范：认证、密码、敏感信息、上传 |
| `business-rule.md` | 按需创建 | 业务规则规范：规则 ID、定义位置、配置方式 |
| `data-dictionary.md` | 按需创建 | 数据字典规范：枚举定义、注册方式、取值含义 |

## 使用方式

- 写新代码前先读对应规范文件。
- 实现与规范冲突时：要么改代码，要么改规范并说明理由，不允许默默违反。
- 本目录里带 `TODO` 的段落等同未定义，落地前必须先填。
- 跨迭代技术取舍按 [`adr.md`](./adr.md) 写决策，接受后落到 `docs/architecture/tech/adr.md`。
