# Plan：优化 iteration-to-test.html 的图面清晰度

> 日期：2026-11-19
> 状态：**已完成**
> 范围：只改 `.agents/plan/iteration-to-test.html`，不改 YAML 图、引擎代码与 skill

## 现状问题

用浏览器实际打开并截图后确认：

1. **打回边重叠**：三条「不满意」虚线都用 `topY = 18` 的同一走廊，两条长线完全叠在一起；其中一条标签落在竖线段上，悬空难读。
2. **整图过宽**：内容约 3052 × 720 px，默认视口只有 585 px（普通屏幕也会横向滚动），没有缩放/平移手段。
3. **语义靠猜**：图例只有「回路 = 虚线」，没有说明虚线代表打回、回路上限 3 次；节点全是白底同边框，动作/决策/门禁/人类输入只能靠外形分辨。
4. **正向边斜穿**：`perpendicular` 锚点 + Manhattan 路由在列间产生不必要的折线和跨越，`ba-write-spec → 需求质量门` 还会绕过 `ba-write-prototype` 右侧形成一圈。
5. **阶段不可见**：需求、技术设计、开发构建三段没有视觉分组，只能逐个节点读。

## 改动方案

### 1. 反馈边分走廊（核心）

- 泳道整体下移，顶部预留 **72px 反馈走廊**，专门放打回边。
- 三条打回边各占独立高度（如 y = 20 / 42 / 64），从源节点顶部出发、水平走到目标列、再落到目标顶部，**不再共用一条线**。
- `修订输入 → dev-plan` 继续走底部走廊，单独高度。
- 标签固定在各自水平段中间，带底色衬块；文案改为「不满意 · 回退」「回到规划」。
- 回路上限以图例说明：「打回最多 3 次，超限停住」，不硬编码到每条边。

### 2. 正向边收敛

- 列间正向边统一 `right → left` 锚点 + 正交路由，去掉斜线。
- `ba-write-spec → 需求质量门` 走右侧独立通道进入门禁右侧，不再与 `prototype`、其他边挤在一起。
- 同一列叠放的节点（`ba-write-spec / prototype / 需求质量门`、`plan 确认 / plan 决策` 等）保持现有顺序。

### 3. 视觉编码

- 节点按类型浅色填充：人类输入（蓝）、人类决策（琥珀）、子 agent 动作（绿白）、门禁（双线框）、主会话（灰）。沿用现有 CSS 变量，深色模式同步。
- 泳道左侧增加 96px 固定标题栏，泳道名竖排居中，不再与第一列节点抢位置。
- 顶部增加三段阶段带：**需求澄清 / 技术设计 / 开发构建**，跨对应列，用浅色标签标出；泳道仍是人 / graph-master / 子 agent 三道。
- 节点字号 12 → 13px，子标题 11 → 11.5px；`dev-build` 内部六步保留，字号同步。

### 4. 适配与交互

- 初始调用 `paper.transformToFitContent`（最大缩放 1，不放大），窗口 resize 时重新适配。
- 右上角加工具条：**适应窗口 / 100% / ＋ / －**；支持滚轮缩放、拖拽平移。
- 保持纯静态单文件，不引入新依赖（仍用现有 JointJS CDN）。

### 5. 图例

补齐：

- 实线箭头 = 正向 / 满意
- 虚线箭头 = 打回 / 不满意（回路上限 3 次）
- 批量节点（双层边框）、封死节点（`dev-build`，内部六步不单独成节点）
- 菱形 = 人类决策，平行四边形 = 人类输入，双线框 = 质量门，圆角框 = 动作，六边形 = 主会话入口，圆角矩形 = 提测
